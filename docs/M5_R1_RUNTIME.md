# M5-R1 Runtime / M5-R1 런타임 경계

## Scope / 범위

M5-R1 introduces a bounded renderer runtime surface around the existing deterministic MUSICA MIDI/WAV implementation. The existing renderer remains a reference implementation only; it is not promoted to a production-quality audio engine.

M5-R1은 기존 MUSICA 결정론 MIDI/WAV 구현 주위에 제한된 renderer runtime 경계를 추가합니다. 기존 renderer는 기준 구현으로 유지되며 production-quality audio engine으로 승격되지 않습니다.

## Runtime flow / 런타임 흐름

```text
Music IR v0
  ↓ canonical JSON bytes
SHA-256
  ↓
RendererRequest v0
  ↓ registry lookup
RendererCapability v0
  ↓ fail-closed compatibility checks
ReferenceRendererAdapter
  ├─ render_midi()
  └─ render_wav()
        ↓
AudioQualityReport v0
        ↓
RendererResult v0
```

## Reference renderer identity / 기준 renderer 식별자

- renderer id: `musica-reference-local`
- renderer version: tied to the bounded adapter implementation
- classification: `deterministic`
- input: `music-ir-v0`
- outputs: `midi`, `wav`
- external binary: no
- plugin host: no
- network: no
- reproducibility claim: `byte_exact` for identical validated request + Music IR under the same MUSICA implementation

## Trust boundary / 신뢰 경계

The adapter receives a validated Music IR object plus a validated RendererRequest. It may create files only below the caller-provided workspace. It returns validated metadata and QA evidence. It does not receive a Project object and cannot update refs, branches, accepted revisions, Blueprint state, or Music IR state.

Adapter는 검증된 Music IR 객체와 RendererRequest만 받습니다. 호출자가 제공한 workspace 아래에만 파일을 생성할 수 있으며 검증된 metadata와 QA evidence를 반환합니다. Project 객체를 받지 않으며 ref, branch, accepted revision, Blueprint, Music IR 상태를 갱신할 수 없습니다.

## Output policy / 출력 정책

R1 defines two roles:

- `midi` → Standard MIDI File generated by the existing deterministic serializer;
- `wav` → mono PCM WAV generated by the existing deterministic preview synth.

Requested outputs not declared by capability are rejected before rendering. Result paths are normalized relative to the workspace and verified after rendering.

## Audio QA policy / 오디오 QA 정책

The analyzer uses Python standard-library WAV parsing and PCM sample inspection so results are reproducible without introducing a DSP dependency in R1.

Default baseline:

- duration tolerance: `max(0.05 seconds, target_duration × 0.5%)`;
- silence: zero non-zero PCM samples → `FAIL`;
- clipping: any sample at the signed PCM full-scale endpoint → `FAIL`;
- DC warning: absolute normalized mean > `0.05` → `WARN`;
- loudness/LUFS: `UNKNOWN` in R1.

The policy is intentionally conservative and is a signal-validity baseline, not a perceptual quality score.

이 정책은 신호 유효성 기준선이며 지각적 음질 점수가 아닙니다.

## Failure model / 실패 모델

The boundary fails closed on schema errors, hash mismatch, unknown renderer, incompatible capability, path traversal, undeclared outputs, malformed result metadata, corrupt WAV, failed required QA, or artifact hash mismatch.

A renderer failure cannot alter canonical project authority. / Renderer 실패는 공식 project 권한을 변경할 수 없습니다.
