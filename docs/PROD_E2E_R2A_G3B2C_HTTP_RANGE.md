# G3B2C-R1 — Session-bound accepted WAV Range over localhost / 장시간 승인 WAV 전송

**STACKED DRAFT / 초안** — Issue #205. Depends on G3B2A merged #202 and G3B2B Draft #204 (must merge before G3B2C promotion). This step covers the HTTP transport boundary, an explicit user-only accepted-WAV download link in the first-party Studio native audio panel, and a **real Chromium 12-second user-click/download SHA regression**, not complete Browser 180-second audition UX.

## Explicit route / 독립된 신규 경로
`GET /v0/sessions/{session_id}/audio/stream/accepted.wav` renders the *current accepted revision* with G3B2A/G3B2B. The client supplies no local file path or accepted revision ID. It exposes the derived WAV file via `200 OK`, **single** RFC 7233-style byte `Range` `206 Partial Content`, `416 Range Not Satisfiable` and `Content-Range`, accurate `Content-Length`, stable SHA-based `ETag`, `Accept-Ranges: bytes`, no-store and same-origin headers. `?download=1` adds a fixed safe Content-Disposition filename.

## Bounded resource / 자원 제한
Reads output in at most 1MiB chunks, one live HTTP stream per active Studio session, two per server. Private derived file generated by approved accepted-only renderers, removed at request completion, peer disconnect, stale HEAD or render failure. No WAV returned to entire Python `wav_bytes` by this new endpoint; legacy routes remain intact.

## Verify / 검증 기준
Dedicated workflow with real byte comparison vs exact native legacy short WAV, first-byte and PCM-boundary ranges, suffix range, invalid/multi-range 416, no Accept/HEAD mutation, cross-session denial, source-derived temp cleanup; a *real 180s accepted two-track 48kHz stereo local HTTP byte-range*, explicit 206/34,560,044 Content-Range and 8 decoded channel samples plus peak process RSS <512MiB; real Chromium operator clicks the accepted-only Download link on an independently accepted 12-second two-track Studio project and verifies downloaded WAV SHA and unchanged HEAD; downloadable proof.json + PNG + clicked WAV; inherited complete CI. Upgrade to actual Playwright 180s playback/explicit export and request lifecycle as later G3B2C slices.

## Current limitations / 미완료
- The new native Studio panel offers an explicit accepted-WAV bounded-stream download link when accepted clips exist, hidden for pending Preview. It does not automatically Accept or upload. This separate route does not yet replace existing 180s `/audio/accepted.wav` or `/mixer-routing/media/accepted.wav` Browser UI paths; those may still produce entire WAV bytes in memory during Studio view/projection.
- A **new rendering is performed for each request** (including range seeks): inefficient for browser multi-Range streaming and CPU budgets. A revision-/hash-bound derived-file cache with TTL, cancellation, quota and atomic crash cleanup is required before general release.
- The 12-second first-party Chromium clicked download demonstrates route-to-UI correctness, **not a 180-second human-created Browser project or verified full-song playback/archive reopen**. No authenticated remote deployment, hardware, plugin or commercial-grade claim. Studio listens on loopback only.
- Fail-closed local/source requirements and explicit Preview → Accept still mandatory.
