## Implemented / 실제 변경
- `StudioAudioSurface.preview_audio_edit` and `StudioRoutingSurface.preview_routing_edit` no longer precompute whole-song Python floats and WAV bytes when preparing a candidate exceeding 16MiB. They install a *source-bound pending Preview* without an in-memory WAV. The pending descriptor marks audio unavailable until candidate streaming is explicitly requested, rather than showing accepted audio as if it were pending.
- `render_pending_preview_streamed(service, session_id, preview_id)` accepts **only a trusted already-installed Pending Preview** of `native_audio_edit`, `routing_edit` or `automation_edit` kind. It cross-checks exact session identity, accepted parent branch/HEAD, preview ID, candidate revision ID and canonical candidate Blueprint SHA. Invalid/stale/discarded candidates fail closed.
- A private ephemeral read-only candidate overlay supplies the candidate Blueprint to existing G3B2A/B fixed-window PCM renderers. The real accepted Project branch is not changed, source CAS is still validated, output remains noncanonical, and a cancellation predicate checks live parent HEAD/pending identity at every block. The caller must unlink the derived WAV. 256MiB output cap is inherited.
- Two real independent accepted 180s·48kHz·stereo PCM16 WAV sources: pending **native track gain -6dB** must produce `(2005,-2500)`; pending **routing output change Bus A→Master** must produce `(4000,-2500)` without changing accepted HEAD. Multiple PCM points, stale preview denial, routing Discard without canonical mutation, and **native Preview-derived 180s WAV SHA equal to the WAV rendered only after explicit user Accept** are tested. Linux process peak RSS <512MiB; dedicated **58th permanent CI**.
- Short Preview continues legacy rendering, including existing PCM byte parity and explicit user Accept.
